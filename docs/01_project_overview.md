# 01\_project\_overview（琴音 / kotone プロジェクト概要・システムワークフロー設計書 v3）

## 1\. ドキュメントの目的

本ドキュメントは、OBS Studio 用カスタム音声フィルタプラグインおよびパーソナル声質解析・プロファイル生成ツール「琴音（kotone）」における、ゴール・解決したい課題・全体ワークフロー・MVPスコープ・非機能要件を定義するマスター設計書である。後続のデータモデリング（`02_data_modeling_v3`）、アーキテクチャ設計（`03_architecture_v4`）、および自律型コーディングエージェント（Codex CLI / Gemini CLI / Claude Code）による実装プロンプト（`04_claude_prompts_v3`）の土台とする。

## 2\. プロジェクト背景と解決したい課題

- **配信・録音時の音響課題**: 生のマイク入力（ドライ音声）は発話のダイナミクス（ささやき声〜叫び声）による音量差が大きく、音量を上げるとピーク時にクリッピング（声割れ）が発生し、抑えると聞き取りづらくなる。また、配信シーン（普段の雑談、テンションの高いゲーム配信、ASMR・囁き声配信など）ごとに最適なEQバランス・コンプレッサーの掛かり具合・メイクアップゲインが大きく異なる。  
- **アプローチの選定（案1：オフライン声質解析 ＋ 超低遅延リアルタイムDSP ＋ マルチプロファイル管理）**:  
  - 事前にシーン別の録音データ（WAV）をPython解析ツール（`kotone-profiler`）で統計・スペクトル解析し、個人の声質・シーンに最適化されたDSPパラメータープロファイル（JSON）を生成する。  
  - OBSプラグイン本体（`kotone.dll` / `kotone.so`）は、プロファイル専用ディレクトリ配下のJSONファイルを自動スキャンしてドロップダウン一覧に表示し、名前付きプロファイル（上限なし・推奨5〜10パターン以上）をワンクリックで即座に切り替えられるようにする。さらにOBS上で微調整した値（Mix / Makeup Gain / Ceiling 等）に名前を付けて新しいプロファイルJSONとして保存（Save / Save As）する機能も備える。

## 3\. システム全体ワークフロー

1. **シーン別ドライ音声の収録（ユーザー操作）**:  
   - 普段のトーク用・ゲーム配信用・囁き声用など、シーンごとに素のマイク音声を1〜3分録音してWAV保存する。  
2. **声質解析・名前付きプロファイル生成（`kotone-profiler` CLI）**:  
   - `kotone-profiler analyze --input whisper_voice.wav --name "囁き声配信" --preset warm_podcast --output-dir "%APPDATA%/obs-studio/plugin_config/kotone/profiles/"` を実行する（直接出力先を指定可能）。  
3. **OBSプラグインでのマルチプロファイル切替＆保存（`kotone` OBS Audio Filter）**:  
   - プラグインの「プロファイル選択（Profile）」ドロップダウンに、内蔵プリセット（3種）＋プロファイルフォルダ内の全 `*.json` ファイル（名前付きプロファイル一覧、上限なし）が自動列挙される。  
   - 配信スタイルに合わせてドロップダウンから「普段トーク」「ゲーム配信」「囁き声配信」などを選択すると、音切れゼロ（ロックフリースロット切替）で瞬時に音響設定が切り替わる。  
   - OBSのUI上で「適用度（Mix）」「メイクアップゲイン」「リミッター天井」等を微調整した後、「新規プロファイル名」欄に名前を入力して「現在の設定を新規プロファイルとして保存（Save As New Profile）」ボタンを押すと、プロファイルフォルダに新しいJSONが保存され、即座にドロップダウン一覧へ追加・選択される（上書き保存ボタンも提供）。  
   - OBSのホットキー機能（`obs_hotkey_register_source`）により、登録済みプロファイル（最大10スロット分のクイック切替ホットキー）をショートカットキーやStream Deck等からも切り替え可能にする。

## 4\. スコープ定義（MVP vs 将来拡張）

### 4.1 MVP（本プロジェクトの実装対象）

- **OBS音声フィルタプラグイン本体（C++17 / `libobs`）**:  
  - `OBS_SOURCE_TYPE_FILTER`（`OBS_SOURCE_AUDIO` フラグ）としての登録およびマルチチャンネル（1ch〜8ch）リアルタイムDSP処理。  
  - リアルタイムDSPチェーンの自前実装（純粋C++17実装）：  
    1. Input Trim（入力ゲイン調整）  
    2. High-Pass Filter（2次/4次 Butterworth HPF）  
    3. 8-Band Parametric EQ（BiquadフィルタによるPeaking / Low-Shelf / High-Shelf）  
    4. De-Esser（歯擦音帯域 4kHz〜10kHz のダイナミック減衰）  
    5. Stereo-Linked RMS/Peak ハイブリッド・コンプレッサー（Soft-knee）  
    6. Auto/Manual Makeup Gain（音圧持ち上げ）  
    7. Lookahead Brickwall Limiter（先読みルックアヘッドバッファ付き、天井値保証＆NaNガード）  
  - **名前付きマルチプロファイル管理機能（上限なし）**:  
    - プロファイル格納フォルダ（デフォルト: OBSプラグイン設定ディレクトリ配下の `profiles/`、UIから任意フォルダへ変更可）内の `*.json` を自動スキャン・ソートしてドロップダウンリストへ動的反映（登録数上限なし）。  
    - ドロップダウン選択による即時切替、一覧再スキャン（Refresh List）、現在設定の上書き保存（Save）、および任意の名前を付けて新規追加保存（Save As New Profile）。  
    - OBSホットキー登録（プロファイル1〜10番へのダイレクト切替ホットキー）。  
- **個人声質解析CLIツール（`kotone-profiler` / Python 3.12+）**:  
  - WAV読み込み、ノイズフロア推定、VAD、F0・LTAS・ダイナミクス・歯擦音解析、`--name` 指定付きJSONプロファイル出力。

### 4.2 スコープ外（Non-Goals / 将来プロジェクト「調べ」へ分離）

- プラグイン内での ONNX Runtime / PyTorch リアルタイムニューラル推論（別プロジェクト「調べ / shirabe」として切り出し）。  
- VST3 / AU プラグイン形式としてのビルド。  
- 独自のカスタムGUIウィンドウ（Qtウィジェットの独自描画）の構築。

## 5\. 非機能要件・品質基準

- **リアルタイム性・レイテンシ**:  
  - DSP処理による追加遅延はルックアヘッドリミッターの先読み時間（デフォルト `2.0ms`）のみに限定し、`filter_audio` 内の動的メモリ確保・ファイルI/O・ミューテックスロックを全面禁止する。  
- **声割れ（クリッピング）絶対防止**:  
  - いかなる大声・突発音（+12dBFS相当）でも出力サンプルの絶対値が Ceiling（デフォルト `-1.0 dBFS`）を超えないこと。  
- **プロファイル管理の堅牢性**:  
  - プロファイル数に上限を設けない（メモリ・UIリストともに動的配列 `std::vector` で管理し、100個以上でも破綻しないこと）。  
  - 日本語ファイル名・日本語 `profile_name`（例: `普段トーク.json`, `ゲーム配信_叫び対策.json`, `囁き声配信.json`）を Windows / Linux 双方で文字化け・パス解決失敗なく扱えること。  
  - 保存時のファイル名サニタイズ（Windows禁止文字 `\ / : * ? " < > |` の安全な置換）とアトミック書き込み（一時ファイル `.tmp` へ書いてからリネーム）により、保存中のクラッシュでも既存プロファイルJSONを破損させないこと。
